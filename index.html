Don't have CLMS or vPB yet?

Deploy them from AWS Marketplace in one click before running sensor deployments.

CloudLens Manager (CLMS)

Central management for sensors. Required for any sensor deployment.

  • Version 6.13.076 from AWS Marketplace
  • One VM, public IP, ready in 15 minutes
  • Default UI: admin / Cl0udLens@dm!n
▶ Deploy CLMS

Virtual Packet Broker (vPB)

Optional. For inline traffic processing and VXLAN aggregation.

  • Version 3.15.01 from AWS Marketplace
  • Three-NIC layout with accelerated networking
  • CLI access via two-hop SSH
▶ Deploy vPB

In the AWS Console, the CLMS offer appears as "CloudLens Manager (Preview)" and the vPB offer appears as "CloudLens Virtual Packet Broker". The Deploy buttons above point to the correct offer IDs automatically.

After CLMS finishes initializing (about 15 minutes), open the UI, create a project, copy the project key, then return here to run the sensor deployment.

First-time use of these images requires accepting Marketplace terms. The Portal will prompt you on first deploy, or run az vm image terms accept --publisher keysight-technologies-cloudlens --offer <offer> --plan <plan>.

Get started in 5 steps

Most deployments under 50 VMs complete in 5 to 10 minutes.

  1. 1
    ☑ Check prerequisites 2 minutes

    You need these in place before deploying:

    • AWS account with Reader and Virtual Machine Contributor roles
    • CloudLens Manager (CLMS) deployed and reachable from your target VMs
    • A project key from CLMS (Settings, Projects, API Keys)
    • SSH key (for Linux targets) or admin password (for Windows targets)

    If you do not have CLMS deployed yet, use the Deploy CLMS button above.

  2. 2
    🏷 Tag your EC2 instances 5 minutes

    The deployment discovers VMs by tag. Apply these to every target VM:

    TagValue
    cloudlensyes
    osubuntu or rhel or windows
    envprod (or dev, qa)

    Bulk tag a VPC:

    for vm in $(az vm list -g <RG> --query "[?storageProfile.osDisk.osType=='Linux'].name" -o tsv); do
  az vm update -g <RG> -n $vm --set tags.cloudlens=yes tags.os=ubuntu tags.env=prod
done
  3. 3
    ⚙ Build your config file 1 minute

    Use the wizard below to fill four fields and download terraform.tfvars.

    Jump to wizard ↓

    Tip: the wizard shows the YAML rendering live as you type. Each field has inline help so you know exactly what to enter.

  4. 4
    🚀 Deploy 5 to 60 minutes

    Place your downloaded terraform.tfvars in your working directory, then pick one of the three deploy paths.

    🌐 Tier 1: AWS Console

    One click. No local tools. Best for: trying it for the first time.

    Deploy from Portal

    ☁ Tier 2: CloudShell

    Already authenticated. One curl command. Best for: most customers.

    curl -sSL https://raw.githubusercontent.com/Keysight-Tech/cloudlens-autopilot/main/quickstart.sh | bash

    🐋 Tier 3: Docker

    Reproducible. Pinned versions. Best for: CI or repeat deployments.

    docker run --rm -it -v $(pwd)/terraform.tfvars:/work/terraform.tfvars ghcr.io/keysight-tech/cloudlens-autopilot:latest
  5. 5
    ✅ Verify in CLMS 2 minutes

    Open your CLMS web UI and confirm:

    • Each tagged VM appears as a registered sensor (under Sensors)
    • Custom tags from your config match what you see in CLMS
    • Sensors show as connected and reporting

    Stuck? See the troubleshooting section below or the full troubleshooting docs.

Build your terraform.tfvars

Fill in four fields. Download the file. Run quickstart. That is the whole flow.

1

CloudLens Manager

Where do I find this?

The IP or hostname of your CloudLens Manager deployment. You can find it in your AWS Console under the CLMS VM details, or in the output of your CLMS Terraform deployment.

2

Project key

Where do I find this?

In CLMS web UI: Settings, Projects, API Keys, copy the key for the project you want sensors to register under.

3

Custom tags

What does this do?

These tags are attached to each registered sensor and visible in CLMS. Use them to filter and group sensors (for example: Customer=Acme, Region=us-east-1).

4

Resource groups

What if I leave this blank?

Blank means scan ALL VPCs in your subscription for tagged VMs. List specific RGs (comma-separated) to limit discovery.

Phase 2 — Product Configuration

Once Terraform or CloudFormation finishes, configure the three Keysight products via their web UIs. One-time setup, about 15 minutes end to end.

1

Accept the KVO EULA

KVO blocks all access including the API until the EULA is accepted in the browser. Open https://<kvo-ip>, read the Keysight Software EULA, click Agree, then log in with admin / admin.

⚠ This must be done in the browser. The CLI cannot accept the EULA on your behalf.
2

Activate licenses on KVO

Navigate to Settings › Product Licensing › Activate. Three licenses must be enabled: vPB Advanced, CloudLens Enterprise, and KVO perpetual. If the license server is unreachable, copy the offline activation key from your Keysight portal.

3

Adopt CLMS into KVO

From KVO: Inventory › CloudLens Manager › Discover. Enter the CLMS private IP (the 10.99.1.x address from Terraform outputs) and the CLMS admin credentials (admin / Cl0udLens@dm!n). Status must turn CONNECTED before proceeding.

4

Onboard the vPB to KVO

SSH to the vPB on port 9022 (not 22) with admin / ixia. Then run:

configure terminal
kvo
ip <kvo-private-ip>
port 443
enable
monitored
end
write memory

Back in KVO, the vPB shows up under Inventory › Devices. Adopt it with Control the adopted device enabled (default). A Device Config is auto-created, and the vPB will now appear in port-binding dropdowns.

5

Create the AWS Cloud Config

On KVO: Cloud Fabric › Cloud Configs › New › AWS. Paste the IAM access key + secret (from terraform output), click Connect, pick the target region + VPC, set the deployment instance type to c5.2xlarge, choose 3 subnets, and commit. KVO will auto-deploy collector SVMs as Service VMs.

Phase 3 — Sensor Deployment via SSM

Push CloudLens sensors to every tagged EC2 instance at fleet scale. No SSH. No WinRM. Just AWS Systems Manager and outbound HTTPS from each VM.

🏷 Tag targets first

Apply two tags to every target EC2 instance. Without these the SSM Document skips the host.

OSTag Platform
Ubuntu / Debianlinux-docker
RHEL / CentOS / Amazon Linux 2023linux-podman
Windows Server 2016+windows

And the marker tag: cloudlens = true

🪪 IAM role on every target

Each VM needs the managed policy AmazonSSMManagedInstanceCore attached to its instance profile. Our prep-targets.sh script can attach this for you and verify the SSM Agent is running.

./scripts/prep-targets.sh \
  --region us-east-1 \
  --profile autopilot

📡 SSM Agent reachability

Each VM must reach ssm.<region>.amazonaws.com, ec2messages.<region>.amazonaws.com, and ssmmessages.<region>.amazonaws.com on 443 outbound — or have a VPC endpoint to those services.

Run the deployment

# Deploy to ALL tagged targets in the region
./scripts/deploy-sensors.sh \
  --region us-east-1 \
  --profile autopilot \
  --clms-ip <clms-public-ip> \
  --project-key <clms-project-key>

# Targeted: only Windows
./scripts/deploy-sensors.sh --platform windows --region us-east-1 --profile autopilot

# Dry run: see what would happen, no changes
./scripts/deploy-sensors.sh --dry-run --region us-east-1 --profile autopilot

The script ships with live progress bars, per-platform targeting, and dry-run. SSM Run Command invokes the CloudLens Sensor installer on every matching VM in parallel — Docker on Linux, MSI on Windows. Status streams to AWS Systems Manager › Run Command › Command History.

Phase 4 — AWS Traffic Mirroring

KVO natively manages AWS VPC Traffic Mirroring. Auto-deploys collector SVMs, creates Mirror filters / targets / sessions, and auto-scales by tapped-interface count. No custom Lambda needed — but ours is included.

1   IAM ready out of the box

Terraform/CloudFormation already provisions an IAM user with the full CloudLens v6.13.0 12-statement policy, scoped with the cloudlens:monitored:vpcid condition tag. Includes EC2, Traffic Mirror, Auto Scaling, and Launch Template permissions.

2   Auto-mirror Lambda

Our optional Lambda + EventBridge rules fire on RunInstances, CreateTags, and instance state changes. Auto-tags new EC2 instances with cloudlens-mirror = true in watched VPCs/subnets. KVO picks up the tag and starts mirroring instantly — no polling.

3   Outpacing Gigamon

Gigamon GigaVUE-FM uses ATS (Automatic Target Selection) which polls the AWS APIs on an interval. Ours fires on EventBridge — sub-second from tag to mirror session. No polling overhead, no missed targets.

4   Monitoring Policies

In KVO: Cloud Fabric › Monitoring Policies › New. Pick the source (tag-based: cloudlens-mirror = true), the tool (vPB + downstream analytics), and KVO will deploy collector SVMs, configure the mirror sessions, and route packets.

Teardown

Clean removal of sensors and infrastructure. Always run in this order — sensors first, infrastructure second.

Step 1 — Remove sensors via SSM

# Remove from ALL platforms
./scripts/remove-sensors.sh --region us-east-1 --profile autopilot

# Or scope to one platform
./scripts/remove-sensors.sh --platform docker --region us-east-1 --profile autopilot
./scripts/remove-sensors.sh --platform podman --region us-east-1 --profile autopilot
./scripts/remove-sensors.sh --platform windows --region us-east-1 --profile autopilot

Step 2 — Destroy infrastructure

Terraform path:

cd terraform/environments/demo
terraform destroy -var-file=demo.tfvars

CloudFormation path:

aws cloudformation delete-stack \
  --stack-name cloudlens-demo \
  --region us-east-1

aws cloudformation wait stack-delete-complete \
  --stack-name cloudlens-demo \
  --region us-east-1

Common issues

If something does not work, check these first.

I don't have CLMS yet. Where do I start?

Use the Deploy CLMS button at the top of this page. CLMS comes from AWS Marketplace, deploys in 15 minutes, and is ready before you start tagging your VMs.

vPB just deployed. Why can't I SSH yet?

Expected: vPB takes 10 to 15 minutes after the AWS deployment finishes before SSH on port 22 is reachable. The VM itself is up, but the internal CLI service and SSH daemon are still initializing.

What to do: wait 15 minutes after deploy succeeds, then try ssh -p 9022 admin@<vpb-public-ip> (vPB SSH is on port 9022, NOT 22, default password: ixia).

Same applies to CLMS: the web UI on port 443 is usually ready within 60 seconds, but full system initialization (including the registry and project creation) takes around 15 minutes.

Inventory finds 0 VMs

Cause: tags missing or misspelled.

Fix: verify with az vm show -g RG -n VM --query tags. The cloudlens, os, and env tags must all be present.

SSH Permission denied

Cause: your public key is not on the target VM.

Fix: bootstrap with az vm run-command invoke to push your key, then re-run the deploy.

SSM Run Command timeout on Windows VMs

Cause: SSM Run Command disabled by default on Windows Server.

Fix: run playbooks/bootstrap_windows_ssm.yaml first to enable SSM Run Command via AWS Run Command.

Sensor does not appear in CLMS

Cause: wrong project key, or sensor cannot reach CLMS network.

Fix: double-check the project key from CLMS UI. Verify the VM can reach CLMS on port 443.

How long should this take?

1 to 50 VMs: 5 to 10 minutes.

50 to 500 VMs: 15 to 30 minutes.

500 to 2000 VMs: 30 to 60 minutes.

Thousands: sharded automatically, 30 to 60 minutes for up to 10K.
